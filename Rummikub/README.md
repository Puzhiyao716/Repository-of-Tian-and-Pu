# 卡牌游戏“完美分组”求解器 (Card Game Solver)

本项目是一个用于判断特定卡牌游戏当前手牌是否“可胜利”的 Python 求解器。它能够快速计算出当前手牌是否能被完美划分为合法的牌组，并给出具体的分组方案。

---

## 📖 游戏规则

### 1. 牌组构成
- 游戏共使用 **104 张牌**。
- 包含 4 种颜色：**红 (Red)、黄 (Yellow)、蓝 (Blue)、黑 (Black)**。
- 每种颜色包含数字 **1 到 13**，且每个数字有 **2 张**（即 $13 \times 4 \times 2 = 104$ 张）。

### 2. 游戏流程
- 这是一个单人游戏。
- 玩家初始抽取 **14 张牌**。
- 玩家尝试将手中的牌按照规则进行分组。
- 如果无法将所有手牌全部分组（即有剩余牌），则从牌堆**摸 1 张牌**，再次尝试分组，以此循环。

### 3. 分组规则
每个合法的牌组必须**至少包含 3 张牌**，且满足以下两种条件之一：
- **顺子 (Run)**：数字严格连续递增（如 4-5-6），且**所有牌颜色必须相同**。
  - *注意：1 和 13 不相连，即 12-13-1 或 13-1-2 是非法的。*
- **同数 (Set)**：数字完全相同，且**每张牌的颜色必须互不相同**（如 红7-黄7-蓝7）。
  - *注意：由于只有 4 种颜色，同数组的大小只能是 3 张或 4 张。*

### 4. 胜利条件
- **完美分组**：手中的所有牌必须全部被分配到合法的牌组中，**不能有任何剩余**。
- 每张牌只能属于一个牌组，不能重复使用。

---

## 💡 代码思路与核心算法

判断手牌是否能完美分组，本质上是一个**精确覆盖问题 (Exact Cover Problem)** 的变种，类似于麻将的“胡牌”判定。由于组合方式多样，本项目采用了**回溯法 (Backtracking) 结合强力剪枝策略**来实现。

### 1. 数据结构：计数矩阵
放弃使用对象列表或字符串数组，采用 **$4 \times 13$ 的二维整数矩阵** `count[color][rank]` 来表示手牌。
- **优势**：状态的读取、修改（加减牌）和复制都是 $O(1)$ 的数组索引操作，比哈希表或列表查找快一个数量级，极大提升了递归搜索的速度。

### 2. 搜索策略：锚点剪枝 (Anchor Strategy)
在普通的回溯中，如果盲目尝试所有可能的牌组，会导致大量的重复搜索和排列爆炸。本项目引入了“锚点策略”：
- **核心思想**：每次递归时，找到当前手中**数字最小（若数字相同则颜色最靠前）的一张牌**作为“锚点”。
- **强制约束**：这张锚点牌**必须**被分配给某个合法的牌组。因此，算法只需要枚举**所有包含该锚点牌的合法组**，而无需考虑不包含它的组。
- **效果**：这不仅保证了每张牌最终都会被处理，还彻底消除了因“先选组A再选组B”和“先选组B再选组A”带来的重复搜索分支，将搜索空间压缩到极小。

### 3. 合法性校验
- **顺子生成**：以锚点为基准，向左右延伸寻找同色连续牌，枚举所有包含锚点且长度大于等于3的顺子。
- **同数生成**：统计与锚点同数字的其他颜色牌，使用组合数学（Combinations）生成包含锚点的大小为 3 或 4 的组合。

## ⚙️ 代码流程说明

代码的执行流程分为三个主要阶段：

### 阶段一：输入解析 (`parse_hand`)
1. 接收字符串列表格式的输入（如 `["R1", "Y5", "B5", "K5"]`）。
2. 将颜色字符映射为 0-3 的整数，数字映射为 0-12 的索引。
3. 填充 $4 \times 13$ 的计数矩阵，并校验单张牌的数量是否超过上限（2张）。

### 阶段二：核心求解 (`solve`)
1. **寻找锚点**：扫描计数矩阵，找到第一张数量 $>0$ 的牌（即最小牌）。如果找不到，说明所有牌已分完，返回 `True`（胜利）。
2. **生成候选组**：调用 `get_valid_groups_for_anchor`，生成所有包含该锚点且符合规则的牌组。如果没有候选组，说明该锚点无法被消除，返回 `False`（回溯）。
3. **尝试与回溯**：
   - 遍历候选组，从计数矩阵中扣除该组的牌（`delta = -1`）。
   - 递归调用 `solve` 进入下一层。
   - 如果递归返回 `True`，说明找到了解，直接向上层返回成功。
   - 如果递归返回 `False`，说明当前选择错误，将扣除的牌加回（`delta = +1`），尝试下一个候选组。

### 阶段三：结果输出 (`check_winnable`)
1. 接收求解器返回的布尔结果和路径记录（`path`）。
2. 如果可胜利，将路径中的整数索引反向解析为人类可读的字符串格式（如 `['红1', '红2', '红3']`）。
3. 返回最终的分组方案列表，或返回 `None` 表示无解。
